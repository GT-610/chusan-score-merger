# 中二节奏 分数合并器

把落雪导出的成绩合并进 RinNET 存档。全过程在浏览器本地完成，文件不上传、不经过任何服务器。

[English](README.en-US.md)

## 特性

- **单调合并。** 分数、灯号、FC、AJ、FULL CHAIN 各自独立取较高者，任何记录都不会被降级。
- **通关状态与分数相互独立。** 分数更高的未通关成绩同样会被合并，因为这是两个独立维度。
- **评价由分数推出。** `scoreRank` 由 `scoreMax` 计算得出；CSV 的 `rank` 列仅作交叉校验，不符时会告警。
- **不编造游玩次数。** 工具无从得知真实的游玩次数，因此 `playCount` 一律不动。
- **全程本地。** 合并在标签页内的 Web Worker 中执行，不存在后端。

## 使用方法

1. 从 RinNET 导出 JSON 存档。
2. 从落雪导出 CSV 成绩列表。
3. 打开页面，选择两个文件并合并。
4. 查看报告，确认无误后下载。
5. 把新文件导入 RinNET。

报告会展示新增成绩、带字段级前后对照的更新记录、枚举与评价告警，以及因条件不满足而跳过补写游玩记录的曲目。**原始存档永不被修改**，输出为新的 `{原名}_merged.json`。

## 合并规则

| 字段 | 规则 |
|---|---|
| `scoreMax` | 取最高分 |
| `scoreRank` | 由 `scoreMax` 推出，不采信 CSV |
| `isSuccess`（灯号） | 取较高灯号 |
| `isFullCombo` | 任一来源存在 FC 即为 FC |
| `isAllJustice` | 任一来源存在 AJ 即为 AJ（并蕴含 FC） |
| `fullChain` | 取较高等级 |
| `playCount` | 不修改 |

`missCount` 恒有值，无 FC 时写 `0`。服务器把这些字段建模为固定位置的非空整数，缺失字段比写 `0` 更危险。

新记录会写入完整字段集。`maxComboCount` 与 `maxChain` 保持 `0` —— 导出数据不含连击信息，编造一个看似合理的数字不如诚实地留零。

## 评价阈值

评价是分数的严格函数，14 个等级区间互不重叠：

| 评价 | 分数区间 | | 评价 | 分数区间 |
|---|---|---|---|---|
| D | 0 – 499,999 | | SS | 1,000,000 – 1,004,999 |
| C | 500,000 – 599,999 | | SS+ | 1,005,000 – 1,007,499 |
| B | 600,000 – 699,999 | | SSS | 1,007,500 – 1,008,999 |
| BB | 700,000 – 799,999 | | SSS+ | 1,009,000 – 1,010,000 |
| BBB | 800,000 – 899,999 | | | |
| A | 900,000 – 924,999 | | | |
| AA | 925,000 – 949,999 | | | |
| AAA | 950,000 – 974,999 | | | |
| S | 975,000 – 989,999 | | | |
| S+ | 990,000 – 999,999 | | | |

CSV 的 `rank` 列仅作交叉校验。与分数不符的行会列在「提示」标签页中。

## 游玩记录补写

补写最近游玩记录默认开启，可在界面关闭。有两条硬性约束：

- **仅写入带有 `play_time` 的行。** 不用 `upload_time` 兜底 —— 一次上传往往包含很多首曲目，上传时间不能代表游玩时刻。缺少时间的曲目会被跳过并列出。
- **ULTIMA 不写入。** 服务端的最近游玩查询会排除该难度，写入也不会显示。

`sortNumber` 是场次 ID 而非时间戳，同一局三首共享一个值。注入的条目从现有最大值之上依次分配。`playDate` 为游玩当日零点，`userPlayDate` 为实际时刻，两者均不带时区偏移。

## 未知取值

未知枚举值回落为 `0` 并继续合并。每次回落都会被记录，并在「提示」标签页中连同曲目与原始值列出，使静默降级不会无从察觉。

### 目录结构

```text
src/
  core/          合并内核：纯函数，不涉及 IO
    types.ts       存档类型定义
    constants.ts   阈值表、灯号表、FULL CHAIN 表
    csv.ts         RFC 4180 解析器
    merge.ts       合并与游玩记录注入
  worker/        Web Worker 入口与消息契约
  ui/            页面控制与样式
test/
  core.test.ts       解析器与阈值表
  merge.test.ts      合并规则
  output.test.ts     下载产物的字节级校验
```

合并内核是一组不涉及 IO、时钟与随机数的纯函数，因此可以直接单元测试。

## 部署

`wrangler.jsonc` 只配置静态资源、不含 Worker 脚本，静态文件由边缘直接吐出而不进入 isolate，Cloudflare 明确将此类请求计为免费且不限量。数 MB 的存档解析与重新序列化需要数十毫秒，而免费套餐每次请求的 CPU 上限只有 10 ms，Worker 无法稳定满足。放在客户端同时也让玩家数据不经过服务器。

```bash
bun run build
npx wrangler deploy   # 需要先登录 Cloudflare
```

不要开启 `run_worker_first`：免费套餐一旦超配额，它会返回 429 而不是回退到静态资源，页面会直接不可用。
